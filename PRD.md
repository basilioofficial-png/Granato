# granato — Product Requirements Document (MVP 1.0)

## 1. Суть продукта

**granato** (Гранат) — персональное мобильное приложение для осознанного управления временем.

Метафора: каждое действие — маленькое зёрнышко граната. Множество зёрен складываются в полную картину дня, недели и жизни человека. Название также отсылает к технике Pomodoro.

### Продуктовая гипотеза

Люди хотят понимать, куда уходит их время, но традиционные инструменты учёта требуют слишком много усилий, поэтому пользователи быстро прекращают вести записи.

**Если фиксация деятельности занимает 1–2 нажатия, а учёт оформлен как ограниченный по времени эксперимент (7, 14 или 30 дней) с итоговым отчётом, пользователь доведёт эксперимент до конца и получит ценные выводы о своём времени.**

### Метрики проверки гипотезы

| Метрика | Что показывает |
|---|---|
| Доля пользователей, завершивших эксперимент | Удерживает ли продукт |
| Полнота учёта (учтённое время / прошедшее время) | Насколько легко вести записи |
| Доля записей `live` против записей задним числом | Используют ли трекинг в моменте |
| Медианное число нажатий на переключение | Выполняется ли обещание «1–2 нажатия» |

## 2. Целевой пользователь

- Человек, который чувствует, что «время куда-то утекает», и хочет это проверить.
- Фрилансеры, специалисты интеллектуального труда, студенты, предприниматели.
- Пробовал таблицы или тайм-трекеры, но бросил из-за трудоёмкости.

## 3. Ключевые понятия

| Понятие | Значение |
|---|---|
| **Категория** (`category`) | Узел дерева сфер жизни. Например: «Работа», «Работа → Совещания», «Работа → Совещания → Встречи с командой». Активность — это тоже категория (узел дерева) |
| **Запись / интервал** (`time_entry`, «зёрнышко») | Отрезок времени, привязанный к одной категории: начало, конец (или «идёт сейчас») |
| **Активная запись** | Запись без времени окончания. Одновременно может быть только одна |
| **Избранное** | Категории, вынесенные в быстрые кнопки на главном экране |
| **Эксперимент** (`experiment`) | Период 7, 14 или 30 дней, в течение которого пользователь осознанно учитывает время |
| **Полнота учёта** | Доля учтённого времени от прошедшего времени периода |
| **Точность учёта** | Доля времени, зафиксированного в моменте (`live`) и не исправленного вручную |

## 4. Пользовательские сценарии

### С1. Первый запуск
1. Пользователь открывает приложение.
2. Видит стартовый набор категорий (Работа, Отдых, Сон, Еда, Дорога, Спорт, Быт), которые можно изменить.
3. Сразу может нажать на любую категорию и начать отслеживание. Регистрация не требуется.

### С2. Начать активность
1. На главном экране пользователь нажимает быструю кнопку, например «Работа».
2. Запускается запись. На экране видны текущая активность и прошедшее время.

### С3. Переключиться (ключевой сценарий)
1. Во время активности «Работа» пользователь нажимает «Еда».
2. «Работа» автоматически завершается в этот же момент, «Еда» начинается. Одно нажатие.

### С4. Закрыть приложение и вернуться
1. Пользователь начинает активность и закрывает или выгружает приложение (или перезагружает телефон).
2. Через несколько часов открывает приложение.
3. Видит ту же активность и корректную продолжительность, рассчитанную по времени начала.

### С5. Детализация
1. Пользователь создаёт внутри «Работы» подкатегорию «Совещания», а внутри неё — «Встречи с командой».
2. Записывает время на любой уровень: на «Встречи с командой» или просто на «Работу».
3. «Отдых» при этом можно оставить без подкатегорий.

### С6. Остановить учёт
1. Пользователь нажимает «Стоп». Активная запись завершается.
2. Время после остановки считается неучтённым (пропуск).

### С7. Просмотр истории дня
1. Пользователь открывает «Историю» и выбирает день.
2. Видит хронологию записей и пропуски между ними.

### С8. Исправление истории
- **Изменить интервал**: сдвинуть начало или конец записи.
- **Разделить запись**: «Работа 10:00–13:00» → «Работа 10:00–12:00» + «Обед 12:00–13:00».
- **Добавить пропущенную запись** задним числом («вчера с 19 до 21 был спорт»).
- **Исправить ошибку**: сменить категорию, удалить запись (с возможностью отмены).
- Если изменение создаёт пересечение с соседней записью, приложение не допускает наложения и предлагает подрезать соседнюю запись.

### С9. Аналитика
1. Пользователь открывает «Аналитику» и выбирает период: день, неделю или произвольный.
2. Видит распределение времени по категориям верхнего уровня, может раскрыть категорию до подкатегорий.
3. Видит общее учтённое время, полноту и точность учёта.
4. Может сравнить два периода (например, эту неделю с прошлой).

### С10. Эксперимент
1. Пользователь начинает эксперимент на 7, 14 или 30 дней.
2. На главном экране видит прогресс («День 5 из 14») и полноту учёта.
3. По окончании получает сводный отчёт: распределение по категориям, полнота и точность, изменения по дням, самые крупные «пожиратели» времени.

## 5. Состав MVP 1.0

### Входит
- Трекинг: старт, стоп, мгновенное переключение, одна активная запись, таймер, быстрые кнопки избранного.
- Восстановление состояния после закрытия приложения и перезагрузки.
- Полная работа без интернета.
- Иерархия категорий произвольной глубины, избранное, архивирование.
- История: хронология дня, правка интервалов, разделение, записи задним числом, удаление с отменой.
- Аналитика: день, неделя, произвольный период, сравнение периодов, детализация по иерархии, учтённое время, полнота, точность.
- Эксперименты 7/14/30 дней с прогрессом и итоговым отчётом.
- Аккаунт (Supabase Auth) и синхронизация данных на сервер (на поздних этапах MVP).

### Не входит в MVP
- ИИ-аналитик (версия 2.0; архитектура его допускает).
- Несколько активностей одновременно.
- Работа на нескольких устройствах одновременно с разрешением конфликтов.
- Виджеты, Live Activities, Apple Watch.
- Push-уведомления и напоминания (кандидат на версию 1.1).
- Командные и социальные функции.
- Экспорт данных (кандидат на версию 1.1).
- Веб-версия.

## 6. Нефункциональные требования

| Требование | Критерий |
|---|---|
| Скорость фиксации | Переключение активности — не более 2 нажатий с главного экрана |
| Надёжность | Ни одно подтверждённое действие не теряется при закрытии приложения, перезагрузке или отсутствии сети |
| Точность времени | Продолжительность считается по сохранённым меткам времени; погрешность определяется только часами устройства |
| Офлайн | Все функции MVP, кроме входа в аккаунт и синхронизации, работают без интернета |
| Приватность | Пользователь видит только свои данные (RLS на сервере); секретные ключи не хранятся в приложении |
| Платформа | Основная — iOS (iPhone); Android поддерживается Expo, но тестируется во вторую очередь |
| Язык интерфейса | Русский |

## 7. Ограничения и допущения

- Время берётся из системных часов устройства. Если пользователь вручную переведёт часы, интервалы могут исказиться. Приложение обнаруживает явные аномалии (отрицательная длительность) и показывает их, а не скрывает.
- В MVP предполагается одно устройство на пользователя.
- На этапах разработки приложение запускается через Expo Go; для финальной сборки используется development build (EAS).
- Пока приложение закрыто, таймер не «тикает» — это не нужно, так как длительность вычисляется по времени начала.

## 8. Критерии готовности MVP 1.0

1. Все сценарии С1–С10 выполняются на реальном iPhone.
2. Первый технический ориентир выполнен: начать активность → закрыть приложение → вернуться → видна корректная продолжительность; при переключении предыдущий интервал автоматически завершается.
3. Логика времени и аналитики покрыта автоматическими тестами, все тесты проходят.
4. В аналитике нет двойного подсчёта: сумма по категориям верхнего уровня равна общему учтённому времени.
5. Пересечения интервалов невозможны через интерфейс.
6. Данные пользователя защищены RLS-политиками, проверка доступа к чужим данным выполнена.
7. Приложение без сети работает полностью (кроме входа и синхронизации).
8. Пройден 7-дневный эксперимент основателя продукта на собственном телефоне.

## 9. Версия 2.0 (ориентир)

Персональный ИИ-аналитик: поиск закономерностей, анализ распределения времени, рекомендации по оптимизации. Работает на сервере (Supabase Edge Function), получает обезличенные агрегаты аналитики. Ключи ИИ-провайдера хранятся только на сервере.
