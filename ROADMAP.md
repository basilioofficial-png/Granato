# granato — Roadmap MVP 1.0

Разработка идёт небольшими проверяемыми этапами. Следующий этап начинается только после приёмки предыдущего основателем продукта.

После каждого этапа предоставляется отчёт: что сделано, какие файлы изменены, какие проверки выполнены и их результаты, что проверить вручную, какой следующий шаг.

**Как проверять на iPhone:** на компьютере выполнить `git pull`, `npm ci` (ставит пакеты строго по `package-lock.json` и не меняет его, в отличие от `npm install`), `npx expo start`, затем отсканировать QR-код камерой iPhone (откроется Expo Go) или выбрать проект в разделе Development servers в Expo Go. Компьютер (`npx expo login`) и Expo Go должны быть залогинены в один и тот же аккаунт Expo. Телефон и компьютер должны быть в одной Wi-Fi сети; если нет — `npx expo start --tunnel`.

## Этап 2. Domain: логика времени ✅
- Типы `TimeEntry`, `Category`, `Interval`.
- Функции: длительность (с учётом активной записи и `now`), старт/стоп/переключение как чистые преобразования, проверка пересечений, обрезка интервала по периоду, деление по дням с учётом часового пояса.

**Критерии приёмки:**
- Тесты: переключение без зазора и наложения; запись через полночь; переход на летнее время; отрицательный интервал отклоняется; повторный старт той же категории ничего не меняет.
- Все тесты проходят.

## Этап 3. Локальная база SQLite ✅
- Подключение `expo-sqlite`, режим WAL, система миграций (`PRAGMA user_version`).
- Миграция `001_init`: таблицы `categories`, `time_entries`, `experiments`, `app_meta`, уникальный индекс активной записи.
- Репозитории `categoriesRepo`, `timeEntriesRepo`.
- Стартовый набор категорий при первом запуске (на этапе 5 заменён набором из макета) — реальные данные пользователя, которые можно менять.

**Критерии приёмки:**
- При первом запуске создаются стартовые категории, при повторном — не дублируются.
- Данные сохраняются после полного закрытия приложения.

## Этап 4. Ядро трекинга ⭐ (первый технический ориентир) ✅
- `trackingService`: `start`, `stop`, `switch`, `getRunning` — транзакционно.
- Zustand-store для активной записи.
- Минимальный экран: список категорий, текущая активность, тикающий таймер, кнопка «Стоп».
- Восстановление активной записи при запуске.

**Критерии приёмки (проверка на iPhone):**
1. Начать активность → выгрузить приложение из памяти → открыть через несколько минут → продолжительность корректна.
2. Во время активности A нажать B → A завершена, B начата в тот же момент (видно в отладочном списке записей).
3. Быстрый двойной тап не создаёт две записи.

## Этап 5. Главный экран 🟨 (ожидает проверки на iPhone)
По макету `docs/design/granato-mockup.html`.
- Дизайн-система: токены, светлая/тёмная тема, шрифты Sora и Manrope, иконки, логотип.
- Вкладки «Трекер», «История», «Аналитика», «Профиль» (три последние — заглушки до своих этапов).
- «Трекер»: карточка текущей записи (путь, название, таймер, «Начато в», «Сменить активность», «Стоп»), пустое состояние с «Быстрым стартом», «Зёрна дня», плитки недавних.
- Шторка «Выбор активности»: поиск, недавние, категории с переходом вглубь.
- Тост «Записано… · Отменить» после переключения и остановки.
- Новый стартовый набор категорий; сброс локальных данных в режиме разработки.

**Критерии приёмки:**
- Переключение на недавнюю активность — одно нажатие; на любую категорию — «Сменить активность» + выбор.
- Отмена возвращает предыдущую запись активной без потери времени.
- Светлая и тёмная тема соответствуют макету.

## Этап 6. Категории 🟨 (ожидает проверки на iPhone)
- Экран «Категории» (Профиль → Категории) по макету: дерево до 3 уровней, раскрытие по тапу, меню «…».
- Создание, переименование, цвет (у корневых категорий), перенос в дереве, архив и возврат из архива.
- Ссылки из шторки выбора: «Управлять категориями», «Добавить активность в «X»».
- Порядок: новые категории добавляются в конец уровня (ручная сортировка — после MVP, если понадобится).

**Критерии приёмки:**
- Можно создать «Работа → Совещания → Встречи с командой» и записывать время на любой уровень.
- Архивированная категория пропадает из выбора, но остаётся в истории.

## Этап 7. История: просмотр ⬜
- Хронология выбранного дня, отображение пропусков, переход между днями.

**Критерий приёмки:** записи дня и пропуски отображаются корректно, включая записи через полночь.

## Этап 8. История: редактирование ⬜
- Изменение границ интервала, смена категории.
- Разделение записи на две.
- Добавление записи задним числом (`source = 'manual'`).
- Удаление с возможностью отмены.
- Обработка конфликтов: предложение подрезать соседнюю запись.

**Критерии приёмки:**
- Тесты на разделение и разрешение конфликтов проходят.
- Через интерфейс невозможно создать пересекающиеся записи.

## Этап 9. Domain: аналитика ⬜
- Агрегация по иерархии, учтённое время, полнота, точность, сравнение периодов.

**Критерии приёмки:**
- Тест: сумма по корневым категориям = общее учтённое время (нет двойного подсчёта).
- Тесты на обрезку по периоду и учёт активной записи.

## Этап 10. Экраны аналитики ⬜
- Периоды: день, неделя, произвольный.
- Распределение по категориям с раскрытием до подкатегорий.
- Сравнение двух периодов.
- Показатели: учтённое время, полнота, точность.

**Критерий приёмки:** цифры аналитики совпадают с ручным подсчётом по истории за тот же день.

## Этап 12. Supabase: сервер и аккаунт ⬜
- Проект Supabase, SQL-миграции, RLS-политики, триггер `server_updated_at`.
- Вход по одноразовому коду на email, хранение сессии в `expo-secure-store`.
- Привязка локальных данных к пользователю после входа.

**Критерии приёмки:**
- Проверено: пользователь не может прочитать или изменить чужие строки.
- В репозитории и приложении нет `service_role` ключа.

**Критерии приёмки:**
- Данные появляются в Supabase.
- Без сети приложение работает, после появления сети изменения доезжают.
